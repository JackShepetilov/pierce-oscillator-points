# Точки серии «помеха → генератор Пирса 11 МГц» в явном виде

Здесь лежат отдельные точки серии от 10.11.2026, выгруженные **в явном виде**:
- сырые осциллограммы в CSV;
- каждый шаг обработки, отдельно для каждого из 200 импульсов;
- итоговые числа;
- графики.

Всё это открывается в MATLAB, Excel или любом редакторе, Python для чтения не нужен.

Сейчас выгружена одна точка: **прямоугольник, 10 В, 100 нс** → папка [`rect_A10V_W100ns/`](rect_A10V_W100ns/).

Ниже по шагам написано, как сделать такую же папку для **любой другой точки** серии.

---

## 1. Что лежит в репозитории

```
point_rect_A10V_W100ns\          ← этот репозиторий
├── README.md                    ← этот файл
├── export_point.py              ← программа, которая делает папку точки
├── .gitignore
└── rect_A10V_W100ns\            ← одна точка = одна папка
    ├── 00_README.txt            что в каждом файле и как он посчитан
    ├── 01_raw_CH1_pulse_V.csv   сырая помеха (CH1), 200 импульсов
    ├── 02_raw_CH2_osc_V.csv     сырая генерация (CH2), 200 импульсов, уже ÷10
    ├── 03_frequency.csv         частота каждого импульса
    ├── 04_phantom.csv           «фантом» (синусоида до помехи) каждого импульса
    ├── 05_track_dphi_deg_each.csv   сдвиг фазы в бегущем окне, каждый импульс
    ├── 06_track_amp_rel_each.csv    амплитуда в бегущем окне, каждый импульс
    ├── 07_track_mean.csv        среднее по импульсам
    ├── 08_per_event_result.csv  итог по каждому импульсу
    ├── 09_result.txt            итоговые числа точки
    └── fig1 … fig5 .png         графики
```

Каждая новая точка ложится рядом отдельной папкой, например `gauss_A5V_W200ns\`.

## 2. Что нужно, чтобы сделать новую точку

1. **Python 3** с пакетами `numpy` и `matplotlib`. На ноутбуке лаборатории они уже стоят. На другом компьютере:
   ```bash
   pip install numpy matplotlib
   ```
2. **Серия на диске.** Программа берёт сырые данные из папки
   `C:\Матвей\Наука\Pierce_Oscillator\data\sweep_20261110_144320`.
   Если серия лежит в другом месте, укажите её ключом `--sweep` (см. раздел 5).
3. **Место на диске:** около **160 МБ** на одну точку, почти всё — два сырых CSV.

## 3. Какие точки есть в серии

| Форма | Имя в команде | Амплитуды A, В | Ширины W, нс | Точек |
|---|---|---|---|---|
| прямоугольник | `rect` | 2, 3, 5, 7, 10 | 10, 15, 20, 25, 30, 35, 40, 45, 50, 60, 70, 80, 90, 100, 120, 135, 150, 180, 200, 250, 300, 400, 500 | 115 |

Реально измеренные пик, ширина и площадь помехи лежат в `summary.csv` серии.

## 4. Как сделать новую точку — по шагам

Пример: гауссиана, 5 В, 200 нс.

**Шаг 1.** Открыть PowerShell (или «Командную строку») и перейти в папку репозитория:
```bash
cd "C:\Матвей\Наука\Pierce_Oscillator\data\point_rect_A10V_W100ns"
```

**Шаг 2.** Запустить программу. После имени файла идут три значения: форма, амплитуда в вольтах, ширина в наносекундах.
```bash
python export_point.py gauss 5 200
```

**Шаг 3.** Подождать около 15 секунд. Программа напечатает итог, например:
```
gauss_A5V_W200ns: 200 событий × 39999 точек, шаг 0.40 нс  ->  ...\gauss_A5V_W200ns
  пишу 01_raw_CH1_pulse_V.csv ...
  пишу 02_raw_CH2_osc_V.csv ...
  частота f0 (медиана), Гц: ...
  макс. среднее отклонение фазы (где амплитуда > 0,5), °: ...
  ...
Готово.
```
В репозитории появится папка `gauss_A5V_W200ns\` с тем же набором файлов, что у `rect_A10V_W100ns\`.

**Шаг 4. Проверить.** Сравнить числа из `09_result.txt` со строкой этой точки в
`C:\Матвей\Наука\Pierce_Oscillator\data\sweep_20261110_144320\gauss\summary.csv` (раздел 6).
Должны совпасть.

**Шаг 5. Сохранить в git:**
```bash
git add gauss_A5V_W200ns
```
```bash
git commit -m "Точка gauss 5 В 200 нс"
```

Готово. Для следующей точки — снова с шага 2.

### Несколько точек подряд

Можно одной строкой в PowerShell, например все ширины прямоугольника при 5 В:
```powershell
foreach ($w in 10,20,50,100,200,500) { python export_point.py rect 5 $w }
```
Каждая точка — ~160 МБ и ~15 с, так что 6 точек — ~1 ГБ и ~1,5 мин.

### Если точки нет

Программа скажет, что файла нет, и перечислит, какие точки в этой форме есть. Например:
```
Нет файла: ...\triangle\A10V_W50ns_raw.npz
В ...\triangle есть: A10V_W100ns, A10V_W120ns, ...
```
Частые причины: треугольник с W < 100 нс (таких нет); опечатка в имени формы; ширины нет в списке (раздел 3).

## 5. Другие способы запуска

| Что нужно | Команда |
|---|---|
| указать файл точки прямо | `python export_point.py "C:\...\sweep_20261110_144320\rect\A10V_W100ns_raw.npz"` |
| серия лежит в другом месте | `python export_point.py rect 10 100 --sweep "D:\копия\sweep_20261110_144320"` |
| писать в другую папку | `python export_point.py rect 10 100 --out "D:\выгрузка\rect_10_100"` |
| справка | `python export_point.py -h` |

Повторный запуск для той же точки **перезаписывает** её папку. Сама серия (`*_raw.npz`) **не меняется никогда**.

### Параметры обработки

Они в начале `export_point.py`:

| Параметр | Сейчас | Что это |
|---|---|---|
| `WIN` | 0,3 мкс | длина бегущего окна подгонки |
| `STEP` | 0,1 мкс | шаг окна |
| `REC_PHASE`, `REC_AMP` | 2°, 5 % | порог «восстановилось» |
| `CH2_FIX` | 10 | на сколько делить CH2 (ошибка настройки щупа) |

Если параметры поменять, числа перестанут совпадать с `summary.csv`. Это нормально, но запишите это в сообщении коммита.

## 7. Что надо знать о данных

- **CH2 (генерация) в CSV уже поделён на 10.** Щуп стоял 1:1, а в настройке канала было 10:1.
  В исходных `*_raw.npz` и в `summary.csv` вольты CH2 в 10 раз больше. На фазы и относительную
  амплитуду это не влияет.
- **CH1 (помеха) при A ≥ 7 В обрезан сверху на ~6,4 В** — это край экрана осциллографа. На поиск фронта не влияет.
- **Время 0** — момент запуска осциллографа по фронту помехи. Запись от −8 до +8 мкс, шаг 0,4 нс.
- **Фаза там, где генерация почти пропала, не показана.** На графиках там, где A/A0 < 0,5, фаза пропущена:
  синусоиды почти нет, и фаза получается случайной. В CSV эти числа есть, но верить им нельзя.
- **Фаза попадания** — где была синусоида генерации в момент фронта помехи (0…360°).
  Генератор помехи и схема не синхронны, поэтому фазы попадания покрывают весь круг.
- **Постоянный сдвиг фазы** (через 4…8 мкс после помехи) в этой серии около нуля.
  Сама подгонка даёт ложную «зависимость от фазы попадания» порядка ±0,01…0,14°,
  поэтому `PRC` такого размера — не эффект.

## 8. Открыть в MATLAB

```matlab
M = readmatrix('rect_A10V_W100ns/02_raw_CH2_osc_V.csv');   % 39999 × 201
t = M(:,1);            % время, мкс
x = M(:,2:end);        % 200 импульсов, по столбцу на импульс, В
plot(t, x(:,1)); xlim([-1 3])

R = readtable('rect_A10V_W100ns/08_per_event_result.csv');
plot(R.phase_hit_deg, R{:,3}, '.')     % пик Δφ против фазы попадания
```
Разделитель — запятая, десятичная точка — точка, первая строка — заголовки.

В Excel: «Данные → Из текста/CSV», разделитель «запятая». Сырые CSV (~80 МБ, 40 000 строк × 201 столбец)
Excel открывает медленно. Для них лучше MATLAB.

## 9. Про размер репозитория

Каждая точка добавляет ~160 МБ. Сам git на компьютере с этим справляется.

Если когда-нибудь загружать репозиторий на GitHub: там предупреждение на файлы > 50 МБ и запрет на файлы > 100 МБ.
Сырые CSV одной точки — 77–81 МБ, то есть пройдут, но с предупреждением.
Для большого числа точек лучше Git LFS или не класть сырые CSV в git: их всегда можно
сделать заново командой из раздела 4.
